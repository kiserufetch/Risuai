# Реворк мобильного чата — спецификация

- **Дата:** 2026-09-28
- **Статус:** на ревью
- **Ветка:** `feat/mobile-chat-v2`
- **Макеты (утверждены):** https://claude.ai/artifact/8XHHgSuZUt28xztm941wVT — страница «Раунд 2 · Лента» (страница «Раунд 1» — история выбора направления)
- **Предыстория:** [docs/mobile-adaptation.md](../../mobile-adaptation.md) — фазы 1–3 мобильной адаптации (фундамент, навигация, чат-UX поверх `DefaultChatScreen`)

---

## 1. Цель

Собрать новый экран чата для мобильной оболочки: современный, удобный, отзывчивый, функциональный и приятный. Визуальный язык новый (направление «Лента»), текущий стиль не наследуется.

**Жёсткое условие:** скриптовое поведение персонажей не меняется. CBS, regex-скрипты, триггеры (V1/V2), Lua, HTML/CSS карточек, фон `backgroundHTML`, модули и плагины работают в новом чате так же, как в текущем.

**Критерии готовности**

1. Каждая функция текущего мобильного чата доступна в новом (таблица соответствия, §9).
2. Паритетные тесты рендера проходят на наборе эталонных сообщений (§11.2).
3. Тестовые персонажи из §11.4 работают на 390×844 в эмуляции и на реальных iOS Safari и Android Chrome.
4. `pnpm check` — 0 ошибок, `pnpm test` и `pnpm build` проходят.
5. Десктоп и планшет (`$DynamicGUI` + `DefaultChatScreen`) не изменились.

## 2. Объём

**Входит**

- Экран открытого чата в мобильной оболочке (`$MobileGUI`: ширина меньше 768 px или Lite-сборка): шапка, лента, действия над сообщениями, поле ввода, шторки «+» и действий, редактор сообщения.
- Состояния: генерация, ошибка, новый чат с приветствием, группа, ветка, скрытые от ИИ сообщения.
- Иммерсивный режим (замена темы Waifu на телефоне) и шаблоны Custom HTML внутри новой ленты.
- Точки встраивания плагинов в чате.

**Не входит**

- Боковая шторка чата: список чатов (`SideChatList`), настройки персонажа (`CharConfig`), `DevTool`, нижние вкладки настроек персонажа. Только стыковка с новым чатом.
- Список персонажей, настройки, Realm.
- Десктоп и планшет.
- Playground (`§playground`) — на телефоне недоступен.

## 3. Журнал решений

| # | Вопрос | Решение |
|---|--------|---------|
| 1 | Альтернативные темы чата | Новая база + иммерсивный режим. `''`, `mobilechat`, `cardboard` → новая лента; `waifu` → иммерсивный режим; `customHTML` → шаблон пользователя внутри новой ленты |
| 2 | Как вызывать действия над сообщением | Под последним ответом — постоянная панель; у остальных сообщений долгое нажатие открывает шторку |
| 3 | Подход к коду | Отдельный мобильный чат + ядро `chatCore` в новых файлах; десктопные файлы не трогаем |
| 4 | Визуальное направление | A · «Лента»: ответы персонажа во всю ширину без «пузыря», реплики пользователя в «пузырях» справа |
| 5 | Макеты раунда 2 | Утверждены целиком, включая показанные в них предложения (§10, пункты 2–7, 13). Пункты §10 с пометкой «новое в спецификации» ждут ревью этого документа |
| 6 | Запасной выход | Настройка «Старый мобильный чат» (`legacyMobileChat`, по умолчанию `false`) |
| 7 | `{{metadata::mobile}}` | Не меняем, остаётся `'0'` |
| 8 | Разработка | В ветке `feat/mobile-chat-v2`; в main — когда новый чат полностью готов |

## 4. Визуальный язык

Точные значения — в макетах. Ниже то, что обязательно для реализации.

### 4.1. Токены

Новые токены выводятся из 9 цветов пользовательской схемы (`--risu-theme-*`, выставляются в `colorscheme.ts: updateColorScheme`). Собственной палитры у нового чата нет: любая встроенная или кастомная схема, тёмная или светлая, продолжает работать.

| Токен | Источник | Где используется |
|-------|----------|------------------|
| `--mc-bg` | `--risu-theme-bgcolor` | фон экрана |
| `--mc-surface` | `--risu-theme-darkbutton` | поле ввода, шторки, плашки |
| `--mc-bubble` | `--risu-theme-selected` | «пузырь» пользователя |
| `--mc-group` | `color-mix(in oklab, var(--risu-theme-darkbutton), var(--risu-theme-textcolor) 5%)` | ряды и плитки в шторках |
| `--mc-line` | `--risu-theme-darkborderc` | границы, разделители |
| `--mc-text` | `--risu-theme-textcolor` | текст интерфейса |
| `--mc-text2` | `--risu-theme-textcolor2` | вторичный текст, иконки |
| `--mc-accent` | `--risu-theme-borderc` | отправка, переключатели, активные состояния |
| `--mc-accent-soft` | `color-mix(in oklab, var(--risu-theme-borderc) 18%, transparent)` | фон кнопки «стоп», плиток «+» |
| `--mc-on-accent` | вычисляется в TS: `#ffffff` или `#111111` — что контрастнее с `borderc` | иконки и текст на акценте |
| `--mc-danger` | `--risu-theme-draculared` | опасные действия, ошибка |
| `--mc-glass` | `color-mix(in oklab, var(--risu-theme-bgcolor) 80%, transparent)` + `backdrop-filter: blur(18px)` | шапка |
| `--mc-scrim` | чёрный 55 % (тёмная схема) / 35 % (светлая) | фон под шторками |

- Тип схемы (`light`/`dark`) берётся из `ColorSchemeTypeStore` и выставляется атрибутом `data-scheme` на корне экрана.
- Цвета текста сообщений — прежние `--FontColorStandard/Italic/Bold/ItalicBold/Quote1/Quote2` (текстовая тема пользователя).
- Шрифт — прежний `--risu-font-family` (правило `* { font-family: … }` в `styles.css` не трогаем). Шрифты в макетах иллюстративные.
- С дефолтной схемой RisuAI (`#0f1117` + индиго `#6366f1`) результат близок к макету. Отдельная встроенная схема с палитрой макета («Графит») — по желанию на этапе 6.

### 4.2. Раскладка и размеры

- **Шапка.** Стекло поверх ленты, сверху отступ `--safe-top`, высота контента 56 px.
  - Слева «назад».
  - Затем кнопка идентичности: аватар 36 px, имя (16 px, 600), подзаголовок (13 px, `--mc-text2`): название чата, во время генерации — «пишет ответ…» акцентным цветом.
  - Справа «новый чат» и «меню» (открывает боковую шторку, `MobileSideBar = 1`).
- **Лента.** Поля 16 px, между сообщениями 24 px.
  - Сообщение персонажа — без «пузыря», во всю ширину. Строка имени: аватар 28 px, имя (14 px, 600), справа бейдж модели (если есть `generationInfo` и включены сведения в чате). Ниже тело `.chattext`.
  - Сообщение пользователя — «пузырь» справа: отступ слева 56 px, радиус 20/20/6/20, фон `--mc-bubble`, поля 10×14.
  - Под последним ответом персонажа — панель: ‹ n/N › · разделитель · реролл · копировать · изменить · «ещё». Кнопки 44×44, иконки 19–20 px, цвет `--mc-text2`.
- **Размер текста сообщений.**
  - Обычные сообщения: `1rem × zoomsize/100` (сейчас `0.875rem × zoomsize/100`), межстрочный интервал — прежняя формула `lineHeight × zoomsize/100`.
  - Сообщения со своим UI карточки (`<style>`/`risu-style`, как в текущей проверке для `mobileContentZoom`) рендерятся ровно как сейчас: `0.875rem × zoomsize/100` и CSS `zoom: mobileContentZoom%`. Вёрстка карточек не меняется.
- **Поле ввода.** Плавающая «пилюля»: радиус 28, фон `--mc-surface`, граница `--mc-line`, тень. Снизу отступ `calc(0.5rem + var(--safe-bottom) + var(--kb-inset))`, как в текущем чате. В макете эту роль играют 28 px внизу — там это имитация safe-area iPhone.
  - Слева «+» 44 px.
  - Textarea 16 px (без авто-зума в iOS), растёт до 5 строк, дальше прокрутка внутри.
  - Справа «отправить»: круг 44 px, `--mc-accent`. Во время генерации — «стоп» (квадрат) с кольцом прогресса.
- **Шторки.** Радиус 24 сверху, ручка 36×5, фон `--mc-surface`, под шторкой `--mc-scrim`. Ряды 50–52 px. Группы рядов — контейнеры с радиусом 16 и разделителями 1 px. Опасные действия — отдельной группой цветом `--mc-danger`.

### 4.3. Доступность и движение

- Все интерактивные элементы — не меньше 44×44.
- Контраст текста не меньше 4.5:1 на встроенных схемах.
- У иконочных кнопок есть `aria-label`. Шторки и редактор: `role="dialog"`, `aria-modal`, фокус не выходит за пределы, закрытие по «назад», Escape и тапу по фону.
- `prefers-reduced-motion`: без анимаций появления, курсора и шторок. Скорость остальных анимаций берётся из `--risu-animation-speed`.
- Хаптика: переиспользуем `haptic()` (`ts/gui/haptics.ts`) с существующими паттернами.

## 5. Экраны и поведение

Нумерация совпадает с артбордами раунда 2.

### 5.1. Обычный чат

- Лента показывает окно сообщений (§6.5). Прокрутка вверх подгружает старые.
- Долгое нажатие (500 мс, хаптика; переиспользуем `use:longpress`) на любом сообщении открывает шторку действий (§5.3).
- Тап по тексту при включённом `clickToEdit` открывает редактор. Исключение — тап по элементу с `risu-trigger` или `risu-btn`: он запускает скрипт и редактор не открывает (§10).
- Частичное редактирование выделением (`enableDragPartialEdit`) работает через тот же `PartialEditController`. Блочное (`enableBlockPartialEdit`) зависит от мыши и на тач-экране не включается — фактически как сейчас.
- `HideIconStore` (`hideChatIcon` у персонажа или `hideIcon` у модуля) скрывает аватары и имена в ленте.
- В мультиюзер-комнатах у сообщений пользователей показывается `message.name`; удаление недоступно, как сейчас.

### 5.2. Генерация

- В шапке подзаголовок «пишет ответ…».
- Пока токенов ещё нет, в ленте индикатор «печатает» (три точки). Во время стриминга в конце текста мигающий курсор.
- Над полем ввода плашка этапа: четыре точки соответствуют `chatProcessStage` 1–4, текущая пульсирует. Подпись этапа: «Сборка промпта», «Память», «Генерация ответа», «Обработка». Рядом таймер с начала отправки. Цвета этапов из старого UI не используются.
- «Стоп» вызывает прерывание текущей генерации (как `abortChat`).
- У генерируемого сообщения панель действий скрыта.
- Во время генерации можно набирать текст; отправка заблокирована до её окончания, как сейчас.
- Все режимы `streamingDisplayOptimizationMode` (off/balanced/strong) поддерживаются (§6.5).

### 5.3. Шторка действий с сообщением

- Сверху превью: аватар, имя и две строки текста сообщения.
- **Быстрые действия** (плитки):
  - «Копировать» — всегда (§10);
  - «Изменить» — не для приветствия;
  - «Перевести» / «Показать оригинал» — если задан переводчик;
  - «Озвучить» — если задан `ttsMode` и чат не групповой.
- **Список:**
  - «Ветвь отсюда»;
  - «В закладки» / «Убрать из закладок» — если `enableBookmark`;
  - «Скрыть от ИИ» / «Вернуть ИИ» (`disabled = true`);
  - «Скрыть от ИИ всё до этого места» / «Вернуть» (`disabled = 'allBefore'`);
  - «Перевести заново» и «Изменить перевод» — если переводчик LLM и сообщение переведено;
  - «Сведения о генерации» — если есть `generationInfo`.
- **Опасные:**
  - «Удалить» — с подтверждением, если `askRemoval`;
  - «Удалить это и всё ниже» — с подтверждением.
- **Приветствие** (индекс −1): только «Копировать», «Перевести», «Озвучить».
- **Метка ветки** (комментарий `branchedfrom`): только «Удалить».

### 5.4. Шторка «+» (инструменты)

Заменяет меню ≡. Условия показа пунктов — те же, что сейчас в меню `DefaultChatScreen`.

- **Плитки:**
  - «Файл» (как `postChatFile`: изображения, аудио, видео, txt, po);
  - «Стикеры» — если `useChatSticker` и не группа; открывает шторку ассетов;
  - «Продолжить» — активна, если сообщений не меньше двух и последнее от персонажа;
  - «Автоответ» — заполняет поле ввода.
- **Переключатели:**
  - «Подсказки ответов» (`useAutoSuggestions`);
  - «Переводить мой ввод» (`useAutoTranslateInput`) — если задан переводчик.
- **Пункты:**
  - «Память» — если `showMenuHypaMemoryModal` и включена HypaV2 или HypaV3;
  - «Модули чата» (`ModuleChatMenu`, справа число активных);
  - «Список чатов» — если `showMenuChatList`;
  - «Скриншот чата»;
  - «Easy Panel» — если `enableRisuaiProTools`;
  - «Остановить озвучку» — если `ttsMode` = webspeech или elevenlab;
  - «Авто-режим» — только в группе;
  - «Реролл» — если `sideMenuRerollButton`.
- **«Плагины»:** кнопки `registerButton` с местом `'chat'` (`additionalChatMenu`). Секция скрыта, если кнопок нет.

### 5.5. Редактор сообщения

- Полноэкранный. В шапке «Отмена», заголовок «Изменить» с подзаголовком «Имя · вариант n из N», «Сохранить».
- Текст — исходный `message.data`. На textarea висит класс `.message-edit-area` для хоткея.
- «Сохранить» записывает в БД, как текущий `edit()`.
- «Отмена» закрывает без изменений; если текст правили, сначала спрашивает подтверждение.
- Нижняя панель (над клавиатурой):
  - чипы «\*действие\*» и ««реплика»» оборачивают выделение или вставляют пару символов в позицию курсора;
  - кнопка «вернуть исходное» возвращает текст на момент открытия.
- «Изменить перевод» открывает этот же редактор с текстом перевода и сохраняет в LLM-кэш перевода, как сейчас.

### 5.6. Подсказки и вложения

- **Подсказки** (`useAutoSuggestions`) — горизонтальная лента чипов над полем ввода.
  - Тап отправляет подсказку как сообщение.
  - Долгое нажатие вставляет её в поле для правки.
  - Кнопка обновления перегенерирует подсказки (с подтверждением, как сейчас).
  - Источник и хранение прежние: `chat.suggestMessages`.
- **Вложения.** Внутри «пилюли» над текстом: у изображений — превью, у остальных файлов — чип с именем и размером; у каждого вложения кнопка удаления. Вставка изображения из буфера поддерживается. При отправке вложения добавляются как `{{inlayed::id}}`, как сейчас.
- **Перевод ввода** (`useAutoTranslateInput`): над полем появляется второе поле с переводом, как сейчас.
- **Кнопка «к последнему»** появляется, если пользователь ушёл вверх больше чем на 240 px. Точка на ней — есть непрочитанный ответ.

### 5.7. Новый чат

- **Заметка автора** — если в `creatorNotes` не меньше двух символов и не выставлен `removedQuotes`. Крестик выставляет `removedQuotes = true`, как сейчас.
- **Строка «Ответы персонажа генерирует ИИ»** — всегда в пустом чате, как сейчас.
- **Приветствие** (индекс −1) с меткой «приветствие».
  - Панель: ‹ n/N › (`alternateGreetings`, `fmIndex`), «Копировать», «Озвучить».
  - `{{none}}`, `{{blank}}` и пустое приветствие не показываются, как сейчас.
  - В группах приветствия нет, как сейчас.

### 5.8. Группа, ветка, скрытые, ошибка

- **Шапка группы:** два первых участника стопкой аватаров, название группы, в подзаголовке — имена активных участников.
- **Автор ответа.** Каждый ответ показывает имя и аватар автора по `message.saying` (chaId); если автора найти не удалось — группу. Display-скрипты в группе по-прежнему не выполняются (§7.1).
- **Метка ветки** (`{{specialcomment::branchedfrom::…}}`) — компактный чип по центру. Тап переходит к исходному чату, как сейчас (`changeChatTo` + `foldChatToMessage`).
- **Скрытые сообщения:**
  - `disabled = true` — текст цветом `--mc-text2` и подпись «скрыто от ИИ»;
  - `'allBefore'` — подпись «ИИ не видит это и всё выше».
- **Ошибка генерации** — карточка в ленте: заголовок «Не удалось получить ответ», текст ошибки, кнопки «Повторить» и «Подробнее». Механизм — §6.6.

### 5.9. Иммерсивный режим

- Включается, когда `db.theme === 'waifu'`.
- **Портрет:**
  - Источник по приоритету: текущая эмоция (`getEmotion` / `CharEmotion`, смена с кроссфейдом, переиспользуем `TransitionImage`) → изображение персонажа → если нет ни того ни другого, показывается обычная лента.
  - Метка текущей эмоции над панелью чата.
  - Кнопка «скрыть портрет» в шапке переключает на обычную ленту до конца сессии; `db.theme` не меняется.
- **Шапка** прозрачная, со скримом-градиентом для читаемости.
- **Панель чата** снизу, стеклянная.
  - Высота по умолчанию 60 % экрана, перетаскиванием меняется в пределах 35–90 %. Значение хранится в `localStorage` с try/catch.
  - Если задан `textScreenColor`, он становится фоном панели.
- Настройки Waifu, предназначенные для десктопа (`waifuWidth`, `waifuWidth2`), на телефоне не используются.

### 5.10. Светлая схема

Те же экраны на токенах светлой схемы. Отдельного макета состояния нет — это проверка токенов.

### 5.11. Прочие существующие элементы

- **Плавающий портрет эмоций в обычном режиме** — если `viewScreen !== 'none'` и (группа или не `inlayViewScreen`), как сейчас `ResizeBox`. Маленькое окно справа под шапкой, тап сворачивает и разворачивает, размер меняется перетаскиванием.
- **Фоны.** Порядок слоёв снизу вверх:
  1. `db.customBackground`;
  2. `BackgroundDom` (`backgroundHTML` персонажа + эмбеддинг модулей);
  3. портрет иммерсивного режима;
  4. лента.
- **Плагины:**
  - `registerButton('action')` — вертикальная стопка круглых кнопок 40 px справа под шапкой, не перекрывает шапку;
  - `setChatPanel` — секции `[data-plugin-chat-panel]` над полем ввода.
- **Переход к сообщению** (закладки, «ветка от»): `ScrollToMessageStore` → подгрузка страниц → прокрутка → подсветка на 2 с, как сейчас.

### 6.3. Ядро `chatCore` — обязанности и API

Сигнатуры ориентировочные, точные уточняются в плане.

- `messageRender.ts` — перенос из `Chat.svelte` (`getCbsCondition`, `displaya`) и `ChatBody.svelte`.
  - `getCbsConditions(idx, { firstMessage })` — `{ firstmsg, chatRole }`, роль берётся из сообщения в БД (как сейчас).
  - `prepareDisplayText(text, { charName, idx, cbs })` → `risuChatParser(text, { chara: charName, chatID: idx, rmVar: true, visualize: true, cbsConditions })`.
  - `renderMessageHtml(text, { character, idx, cbs, modelShortName })` → `ParseMarkdown(text, character, 'notrim', idx, cbs)` → `trimMarkdown` → `addMetadataToElement`.
  - `translateForDisplay(...)` — три режима перевода, кэш LLM, три попытки и затем `alertError`, как сейчас.
  - `fixAssetImages(root, character)` — перенос `checkImg` (при `newImageHandlingBeta`).
- `scriptedClicks.ts`
  - `handleScriptedClick(event, { idx, isGroup })` — перенос `handleButtonTriggerWithin`.
  - Ищет `closest('[risu-trigger], [risu-btn]')`; `risu-trigger` приоритетнее.
  - `risu-trigger` → `runTrigger(char, 'manual', { chat, manualName, triggerId })`; `risu-btn` → `runLuaButtonTrigger`.
  - Результат записывается в текущий чат, затем `ReloadChatPointer[idx]++`.
  - Если есть `risu-trigger` и `risu-id`, `CurrentTriggerIdStore` сбрасывается через 100 мс.
  - В группах ничего не делает.
  - Возвращает, был ли клик скриптовым: так `clickToEdit` не срабатывает на кнопках.
  - API: `findScriptedOrigin(target)` — синхронная проверка, которой UI пользуется, чтобы не открывать редактор по тапу на скриптовом элементе, и `handleScriptedClick(event, idx): Promise<void>` — сам обработчик клика.
- `sendPipeline.ts` — перенос из `DefaultChatScreen.svelte`.
  - `sendMessage(text, attachments)` выполняет шаги по порядку:
    1. слэш-команды (`processMultiCommand`);
    2. `{{inlayed::id}}`;
    3. `useSayNothing`;
    4. для одиночного персонажа — `runTrigger(char, 'input', { chat })` (результат заменяет чат), затем `processScript(char, text, 'editinput')`;
    5. в группах — сырой текст;
    6. сообщение `{ role: 'user', data, time, name? }`;
    7. сброс кэша рероллов;
    8. `sendChat(-1, { signal })`;
    9. сброс `doingChat` после успешной генерации.
  - `continueResponse()` — продолжает только последний ответ персонажа: не трогает черновик и не добавляет сообщение пользователя (§10.16). `abortGeneration()`, `requestAutoReply()`, `setGroupAutoMode(on)`.
  - Операции закрепляют стартового персонажа, страницу чата и ключ чата в момент вызова; защита от повторного входа делает так, что повторная отправка возвращает `'busy'`, а повторный запуск генерации — no-op.
- `alternatives.svelte.ts`
  - Реролл по порядку: кэш `Prereroll` → история вариантов → удаление последних ответов персонажа и `sendChat`.
  - «Назад» — `PreUnreroll` / история.
  - Счётчик n/N для панели.
  - **История хранится по id чата** (`Chat.id`) в памяти сессии: не теряется при выходе из экрана и не смешивается между чатами одного персонажа.
- `messageActions.svelte.ts` — перенос `rm`, `edit`, `toggleBookmark`, ветвления, `disabled`, `sayTTS`, `alertRequestData`, переключения `fmIndex`, сохранения правки перевода. Индекс −1 защищён для всех действий, которые его не поддерживают.
- `copyMessage.ts` — копирование сообщения карточкой (HTML + текст) или только текстом, как в `Chat.svelte`.
- `generationStatus.svelte.ts` — `{ running, stage, startedAt, error }`. Этап берётся из `chatProcessStage`. Перехват ошибок — §6.6.
- `messageWindow.svelte.ts` — окно по `chatLoadInitialPages`/`chatLoadAdditionalPages`, cold storage, `chatFoldedStateMessageIndex`, `ScrollToMessageStore`.

### 6.5. Лента и обновления

- Keyed `{#each}` по видимому окну, от новых к старым. Скроллер `column-reverse` держит низ при стриминге (так же, как текущая фаза 3). Новые сообщения первыми в DOM — на это опираются хоткеи и пользовательский CSS.
- **Ключ:** `message.chatId ?? 'idx:' + i`. Если индекс сдвигается (удалили сообщение выше), компонент не перемонтируется: рендер перезапускается с новым индексом.
- **`{#key}` внутри элемента:**
  - `ReloadChatPointer[i]` → полный перемонтаж этого сообщения;
  - `'|raw'` для активного сообщения в режиме `strong` → перемонтаж в начале и конце стрима, как сейчас.
- **`ReloadGUIPointer`** → повторный CBS-проход у всех сообщений и перемонтаж тел.
- **Стриминг:** текст обновляется на месте.
  - off/balanced — полный цикл рендера на каждое обновление; пока новый результат не готов, показывается последний удачный.
  - strong — сырой текст в `span.whitespace-pre-wrap`, как сейчас.
- **Автопрокрутка** — как в текущем `Chats.svelte`: при смене чата — к последнему; после отправки — к последнему; ответ персонажа — по `autoScrollToNewMessage`/`alwaysScrollToNewMessage`, иначе точка «непрочитано».

### 6.6. Перехват ошибок генерации

- Пока идёт генерация, запущенная из нового чата, `generationStatus` подписан на `alertStore`.
- Алерт типа `error` копируется в `error`, а `alertStore` синхронно сбрасывается, чтобы модальное окно не мелькнуло. Ошибка показывается карточкой.
- «Подробнее» открывает прежнее окно через `alertError(исходный текст)`. «Повторить» повторяет последнее действие: отправку, реролл или «продолжить».
- При `inlayErrorResponse` ошибка остаётся внутри сообщения (блок `risuerror`), перехвата нет.
- Остальные алерты (Lua `alertNormal/Input/Select/Confirm`, триггеры, слэш-команды) не перехватываются.

## 7. Контракт совместимости

### 7.1. Рендер

- Используются те же функции в том же порядке и с теми же аргументами: `risuChatParser` (с `rmVar`, `visualize`, `cbsConditions`) → `ParseMarkdown(…, 'notrim', idx, cbs)` → `trimMarkdown` → `addMetadataToElement`. Внутри `ParseMarkdown` по-прежнему выполняются: ассеты, Lua `editDisplay`, триггер display, обработчики плагинов `display`, второй CBS-проход, regex `editdisplay`, dynamicAssets.
- `chatID` — настоящий индекс сообщения; у приветствия −1.
- `character`: `createSimpleCharacter(currentCharacter)`. В группах `null`, поэтому display-скрипты и CBS-ассеты не выполняются — как сейчас.
- Переводы — те же три режима, `edittrans`, кэш LLM с тем же ключом.
- `newImageHandlingBeta` — та же пост-обработка `<img>`.
- HTML вставляется через `innerHTML` в обычный DOM: без shadow DOM и iframe.

## 8. Custom HTML

- Если `db.theme === 'customHTML'`, `MessageItem` вместо своей раскладки рендерит шаблон `db.guiHTML`. Перенос логики `Chat.svelte`: CBS-проход → DOMParser → белый список тегов и атрибутов → сборка элементов.
- Плейсхолдеры:
  - `<risutextbox>` → `MessageBody`;
  - `<risuicon>` → аватар;
  - `<risubuttons>` → `ActionBar` у последнего ответа, у остальных — пусто;
  - `<risugeninfo>` → бейдж модели.
- Корень по-прежнему `.risu-chat[data-chat-index]` с перехватом кликов. Долгое нажатие открывает шторку действий.
- Известное ограничение (как сейчас): `<img>` в шаблоне теряет `src`, `<style>` шаблона становится глобальным.

2. Меню ≡ заменено шторкой «+». Действия с сообщением — панель у последнего ответа и шторка по долгому нажатию.
3. Плашка этапов генерации с подписями и таймером вместо цвета кольца.
4. Полноэкранный редактор с «Отменой» и «Сохранением», чипы `*…*` и «…», «вернуть исходное».
5. Ошибка генерации — карточка в ленте (§6.6).
6. «Скрыто от ИИ» — приглушённый текст и подпись вместо пунктирных линий. Пункты переименованы: «Скрыть от ИИ», «Скрыть от ИИ всё до этого места».
7. В группах у каждого ответа имя и аватар автора.
8. «Копировать» доступно всегда, без настройки `useChatCopy`. *Новое в спецификации.*
9. Тап по элементу `risu-trigger` или `risu-btn` при `clickToEdit` больше не открывает редактор. *Новое в спецификации.*
10. `prose-invert` только в тёмной схеме (сейчас включён всегда).
11. Свайп боковой шторки — только от края экрана.
12. Обычные сообщения на телефоне — 16 px × `zoomsize` вместо 14 px; сообщения с UI карточки — как сейчас (§4.2). *Новое в спецификации.*
13. Кнопка «скрыть портрет» в иммерсивном режиме.
14. Исправления (найдены при исследовании кода):
    - история рероллов больше не теряется при выходе из чата и не путается между чатами;
    - «Ветвь» и «Скрыть» на приветствии не падают;
    - `MobileSideBar` сбрасывается, если чат закрыли не кнопкой «назад»;
    - нет двойного отступа `--safe-top`;
    - плавающие кнопки плагинов не перекрывают шапку.
15. Черновик поля ввода хранится по id чата до конца сессии и не стирается ни рероллом, ни «продолжить». *Новое в спецификации.*
16. «Продолжить» больше не отправляет черновик поля ввода и не добавляет сообщение пользователя (в отличие от старого `sendContinue`, который шёл через `sendMain` и мог отправить черновик или `*says nothing*`) — продолжается только последний ответ персонажа. *Новое в спецификации.*
17. Настройка «Мгновенное удаление» (`instantRemove`) в новый чат не переносится: её заменяют два отдельных пункта шторки — «Удалить» и «Удалить это и всё ниже» (§9). *Новое в спецификации.*

## 11. Тестирование

### 11.1. Модульные (vitest + happy-dom)

- `messageRender`: аргументы вызовов `risuChatParser` и `ParseMarkdown` (моки) для обычного сообщения, приветствия (−1), группы; `getCbsConditions`; ключ кэша перевода.
- `scriptedClicks`: `risu-trigger`, `risu-btn`, `risu-id`; приоритет `risu-trigger`; запись результата; `ReloadChatPointer`; сброс `trigger_id` через 100 мс (fake timers); группы игнорируются; признак скриптового клика.
- `sendPipeline`: порядок шагов, шаги только для одиночного персонажа, `useSayNothing`, вложения, сброс `doingChat`, стоп.
- `alternatives`: история по id чата, реролл/назад/вперёд, счётчик, переход в другой чат.
- `messageActions`: удалить, удалить ниже, ветвь (новый чат с меткой), скрыть и вернуть, закладки, защита индекса −1.
- `generationStatus`: перехват ошибок только пока идёт генерация; сброс `alertStore`; режим `inlayErrorResponse`.
- `schemeTokens`: выбор `--mc-on-accent` для светлого и тёмного акцента.

### 11.2. Паритет рендера

Один и тот же набор сообщений монтируется в happy-dom дважды: старым `Chat.svelte` и новым `MessageBody`/`MessageItem`. HTML внутри `.chattext` сравнивается после нормализации пробелов.

Набор:
- обычный RP-текст;
- markdown (заголовки, код, таблица);
- `{{char}}`/`{{user}}`/`{{chatindex}}`;
- `<style>` с классами (скоупинг `x-risu-`);
- `{{button::…}}`;
- inlay-изображение — покрыто `src/ts/process/files/tests/inlays.test.ts` (IndexedDB недоступна в happy-dom, а разбор inlay у старого и нового пути общий);
- regex `editdisplay`;
- приветствие;
- группа.

Внешние зависимости (Lua/wasmoon, KaTeX, ассеты) мокаются так же, как в существующих тестах парсера (`vitest.setup.ts`).

### 11.3. Компоненты

Монтирование в happy-dom по образцу `src/lib/UI/GUI/guiRendering.test.ts`: DOM-контракт §7.2 (классы, атрибуты, заместители хоткеев), панель только у последнего ответа, пункты шторок по условиям настроек.

### 11.4. Смоук и устройства

- Playwright (MCP) на 390×844, dev-сервер (`.env.local` с `VITE_RISU_LEGAL_CONFIGURED=TRUE`).
- Тестовые персонажи:
  1. Статус-панель через regex + Lua `onButtonClick` + `risu-trigger`.
  2. Шаблон Custom HTML.
  3. Группа из двух персонажей.
  4. Waifu с эмоциями.
  5. Плагин v3 с `registerButton('chat'|'action')` и `setChatPanel`.
  6. Длинный чат (500+ сообщений) со стримингом.
- Реальные устройства: iPhone (Safari: клавиатура, safe-area, `position: fixed`) и Android (Chrome). Портрет и ландшафт, ширина 320 px.

## 13. Риски
